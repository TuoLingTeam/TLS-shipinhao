## 五、架构设计分析

### 5.1 整体架构：分层 + 端口-适配器（Hexagonal / Ports & Adapters）

```
┌──────────────────┐   Tauri invoke       ┌──────────────────────┐
│    Vue 3 UI      │ ──────────────────▶  │   Commands 层         │
│  (前端 SPA)       │      + event emit    │   (IPC 控制器)        │
└──────────────────┘                       └───────────┬──────────┘
                                                       │
                                          ┌────────────▼───────────┐
                                          │  Desktop Services      │
                                          │   (业务服务层)           │
                                          └────────────┬───────────┘
                                                       │
                        ┌──────────────────────────────┼──────────────────────────────┐
                        │                              │                              │
                ┌───────▼──────┐              ┌────────▼───────┐             ┌────────▼───────┐
                │  Domain Core │              │ API Contracts  │             │ License Service│
                │   (领域模型)   │              │   (共享类型)     │             │   (授权抽象)     │
                └──────────────┘              └────────────────┘             └────────┬───────┘
                                                                                      │
                                                                             ┌────────▼───────┐
                                                                             │  Adapters 层    │
                                                                             │ HTTP客户端/SQLite│
                                                                             └────────┬───────┘
                                                                                      │
                                           ┌──────────────────────────────────────────┼──────────────────────────────┐
                                           │                                          │                              │
                                    微信小店 API                              本地 SQLite                    Cloudflare Worker
                                  (store.weixin.qq.com)                    (order_cache.db)              (授权 API + D1 数据库)
```

### 5.2 关键架构特征

#### 5.2.1 端口-适配器模式

业务逻辑在 `crates/license-service` 等库中通过 trait 定义接口（端口），`apps/desktop/adapters/` 提供具体实现（适配器）。优势：

- 业务逻辑不耦合具体 HTTP 客户端或数据库实现
- 可独立进行单元测试（mock 适配器）
- 方便未来切换数据源

#### 5.2.2 Tauri IPC 通信

**请求-响应**：前端 `invoke('command_name', args)` → Rust `#[tauri::command]` 函数处理

**事件推送**：Rust `app.emit('order-sync-progress', payload)` → 前端 `listen('order-sync-progress', handler)`

#### 5.2.3 本地优先（Offline-First）

订单数据缓存到本地 SQLite，`SqliteOrderCache` 适配器提供读写能力，大幅降低对微信小店 API 的依赖与调用频次。

#### 5.2.4 授权服务分离

授权服务独立部署为 Cloudflare Worker（`sphapi.199908.top`），使用 D1 数据库存储卡密与激活记录。桌面端通过 `http_license_client` 与其通信。

**`useTauriInvoke` 核心实现**：

```typescript
import { ref } from "vue";
import { invoke } from "@tauri-apps/api/core";

export function useTauriInvoke<T>(command: string) {
  const data = ref<T | null>(null);
  const error = ref<string | null>(null);
  const loading = ref(false);

  async function execute(args?: Record<string, unknown>): Promise<T | null> {
    loading.value = true;
    error.value = null;
    try {
      const result = await invoke<T>(command, args);
      data.value = result;
      return result;
    } catch (e) {
      error.value = typeof e === "string" ? e : String(e);
      return null;
    } finally {
      loading.value = false;
    }
  }

  return { data, error, loading, execute };
}
```

## 八、错误处理与日志机制

### 8.1 桌面端错误类型

`apps/desktop/src/error.rs`：

```rust
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("{0}")]
    Domain(#[from] domain_core::DomainError),

    #[error("{0}")]
    Internal(#[from] anyhow::Error),

    #[error("{0}")]
    Message(String),
}
```

**特点**：
- 使用 `thiserror` 派生
- 自动从 `DomainError` 和 `anyhow::Error` 转换
- 序列化后通过 Tauri IPC 传递给前端

### 8.2 领域错误

`shared/domain-core/src/lib.rs` 中定义：

- `InvalidTimeWindow` — 无效时间窗
- `OrderCacheMiss` — 订单缓存未命中
- 其他领域相关错误

### 8.3 日志机制

- **主要方案**：`tracing` crate（如 `tracing::warn!`）
- **部分地方**：`eprintln!`（`state.rs` 中 Cookie 加载信息）
- **未发现**：统一的 `tracing_subscriber` 初始化代码

### 8.4 Worker 错误处理

- `Response::error(msg, status)` 返回文本错误
- 自定义 `json_err` 返回 JSON 错误
- `ADMIN_SECRET` 未配置时返回 503 JSON

## 九、认证与授权机制

| 场景 | 机制 | 实现位置 |
|---|---|---|
| **管理员 API** | 请求头 `X-Admin-Secret` 与 Worker Secret 比对 | `admin_d1.rs` `check_admin` |
| **卡密合法性** | D1 `generated_keys` 表存在性检查（卡密为 `admin_generate` 端随机生成的 `TLS-{16hex}`，64 位熵） | `license-worker::admin::admin_generate` + `D1RuntimeRepo::load_generated_key` |
| **Lease 签名** | Ed25519 私钥签名 `LeasePayload`，客户端用硬编码公钥验签；软过期 24h + 硬过期 72h | `license-service` + `license-worker::LeaseTokenSigner` |
| **桌面功能门控** | `ensure_feature_authorized` 检查本地持久化的 `license_state`（`active` / `renewal_due`） | `commands/license.rs` |
| **微信小店接口** | 用户 Cookie + `biz_magic` 参数 | `http_order_search.rs` 等 |

## 十四、代码质量观察

### 14.1 优点

1. **清晰的分层架构**：Rust 代码严格遵循端口-适配器模式，业务逻辑与外部依赖解耦
2. **类型共享**：`api-contracts` crate 统一前后端类型契约
3. **现代技术栈**：Vue 3 setup + Pinia setup store + Tailwind 4 + Vite 6
4. **跨平台考虑**：CI 同时构建 Windows 和 macOS
5. **CSP 约束**：Tauri 配置中启用了 `default-src 'self'`，降低 XSS 风险
6. **Release profile 优化**：开启 LTO、strip、codegen-units=1

### 14.2 值得关注的问题

1. **Worker API 未完整实现**：`/api/activate` 和 `/api/verify` 目前返回占位响应，与 README 文档不符，需要补全 D1 Repository 接入
2. **遗留代码未清理**：`_legacy/`、`app/` 两套 Python 代码并存，可能造成混淆
3. **日志不统一**：`tracing` 与 `eprintln!` 混用，缺少统一的 `tracing_subscriber` 初始化
4. **本地 DB 文件不一致**：`order_cache.db` 与 `order_cache.sqlite3` 同时存在，需澄清用途
5. **根目录 `cookie.txt`**：明文 Cookie 文件（已在 README 中提示需定期更新）
6. **缺少前端 lint 配置**：未找到 ESLint/Prettier 配置文件
7. **未提交改动**：5 个 UI 文件有未提交修改，`main` 领先 origin 6 个 commit

### 14.3 架构风险

| 风险 | 等级 | 说明 |
|---|---|---|
| Cookie 过期 | 🟡 中 | 微信小店接口依赖 Cookie，需定期手动更新 |
| Worker 授权未完整 | 🔴 高 | 核心授权 API 尚未真正对接 D1 |
| 遗留代码共存 | 🟡 中 | 可能造成维护混淆 |
| 缺少自动化测试 | 🟡 中 | 仅见 Python 遗留测试，Rust/前端测试覆盖率未明 |
| 单机 SQLite 并发 | 🟢 低 | 桌面端单用户，风险较小 |
