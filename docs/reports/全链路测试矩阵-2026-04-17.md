# TLS-shipinhao 全链路测试矩阵（2026-04-17）

> 目标：围绕“授权主链 + Worker + 桌面业务 + 前端构建”形成闭环验证。
> 原则：先测通链路，再决定是否需要修复；未拿到失败证据前不盲目改代码。
> 说明：本矩阵分为“可自动化执行”与“需要手工/真实环境”的两类。

## 1. 执行范围

### 1.1 本轮优先覆盖链路

1. **授权 Worker 主链**
   - activate / verify / lease_refresh / task_authorize / lease_revoke / admin_revoke
2. **桌面授权门禁主链**
   - RuntimeState
   - secure_storage
   - task grant
   - integrity gate
3. **桌面业务命令主链**
   - review
   - order sync
   - delivery
4. **共享 Rust crates**
   - domain-core
   - desktop-services
   - license-service
   - security-core 相关能力经 Python/Rust 集成测试覆盖
5. **前端构建链**
   - `apps/ui` 类型检查与构建

### 1.2 暂不在本轮自动化内解决的事项

- 真实线上授权域名切换
- 真实 Keychain / Credential Manager 交互
- 真实桌面窗口 UI 视觉回归
- 真实发货外部接口与真实风控环境

## 5. 本轮自动化结论

- `FL-01 ~ FL-08` 已全部完成，当前自动化闭环成立。
- 本轮唯一出现的真实失败点是 `FL-06` 的 Python 集成测试基线过时：
  - 旧 crate 路径与当前仓库结构不一致；
  - `test_security_runtime.py` 依赖可选包 `cryptography`，本机未安装。
- 处理方式遵循“只做最小修复”原则：
  - 仅修正测试基线与路径断言；
  - 对缺少 `cryptography` 的场景改为 `SkipTest`，不修改业务代码。
- 当前仍待真实环境验证的链路为 `FL-09 ~ FL-14`。
