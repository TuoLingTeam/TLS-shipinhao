## 一、产品画像（PM 视角理解）

### 1.1 产品一句话

> **面向微信视频号小店商家的「批量运维助手」**——自动同步订单、智能匹配差评/品退、批量发货，解决商家在小店后台重复手动操作的痛点。

### 1.2 用户画像

| 维度 | 特征 |
|---|---|
| **角色** | 微信小店卖家 / 客服 / 运营 |
| **规模** | 中小型商家（日均订单 10~1000 单） |
| **核心痛点** | 小店后台操作繁琐、差评定位订单困难、发货录入耗时 |
| **技术能力** | 低（需要手把手引导） |
| **付费意愿** | 中（按卡密/订阅） |

### 1.3 核心价值主张

| 价值点 | 业务价值 |
|---|---|
| **订单本地缓存** | 一次同步多次使用，响应快，减少反复拉取 |
| **差评智能匹配** | 自动把差评关联到具体订单，便于运营介入 |
| **品退订单归集** | 发现质量问题商品，预警库存风险 |
| **批量发货** | 减少 80% 发货录入时间 |

### 1.4 商业模式

**卡密授权制**：
- 用户在独立渠道购买卡密
- 在应用内激活，绑定设备
- 授权状态由 Cloudflare Worker 统一校验（当前占位中）

**严重问题**：从下载到首次成功使用至少经过 **7 步**，其中 5 步有体验缺陷。**首次流失率预计极高**。

### 2.2 日常使用流程（老用户）

```
启动 → 自动校验授权 → 仪表盘 
  ↓
  ├─→ 评价管理：查询差评 → 点击差评行 → 自动跳转发货 ✅
  └─→ 订单管理：同步缓存 → 本地检索订单
  ↓
批量发货（从 Excel 复制 → 粘贴 → 一键发货）
```

**日常路径设计合理**，问题主要在**新手上手成本**和**异常流程处理**。

## 四、UX/UI 体验问题清单

### 4.1 反馈缺失（Feedback Gap）

| 场景 | 现状 | 问题 | 优化 |
|---|---|---|---|
| 单条发货成功 | 仅 `store.error` 清空，无 Toast | 用户不确定是否成功 | 增加成功 Toast |
| 卡密激活成功 | 无明显提示 | 用户反复点击 | 成功后卡片高亮 + 动画 |
| Cookie 保存成功 | 2s 小字提示 | 文字太小、位置不显眼 | 居中 Toast + 对勾图标 |
| 订单同步完成 | 进度消失 | 无完成感 | 显示"同步完成，新增 XX 条" |

### 4.2 信息密度与可读性

| 问题 | 影响 | 优化 |
|---|---|---|
| 差评列表信息太多（买家名、评价、SKU、订单号、分数、匹配状态）混在一行 | 扫视困难 | 卡片化布局 + 关键信息突出 |
| 订单卡片金额显示"分转元"但无货币符号一致性 | 易误读 | 统一 `¥123.45` 格式 |
| 错误提示使用 `store.error` 字符串展示 | 有时后端返回很长 stack | 错误分级：用户错/系统错/网络错 |

### 4.3 异常场景体验

| 场景 | 现状 | 优化 |
|---|---|---|
| Cookie 未配置却点订单同步 | 后端返回中文字符串展示 | 前端前置校验 + 引导跳转 /settings |
| 授权过期 | `soft-alert` 警告条 | 启动弹窗 + 续费入口 |
| 网络断开 | invoke 报错字符串 | 全局网络状态指示器 |
| 匹配 0 结果 | `EmptyState` 文字 | 增加诊断建议："检查 Cookie 是否有效 / 时间范围过短" |

### 4.4 无障碍 / 可用性

| 问题 | 优化 |
|---|---|
| 表单字段无必填标记（`*`） | 增加视觉标识 |
| 按钮禁用状态仅灰色，无原因说明 | 增加 tooltip 说明原因 |
| 键盘操作支持不全 | 所有表单支持 Tab 顺序 + Enter 提交 |

## 五、业务功能深度优化建议

### 5.1 授权模块重构建议 🔴 最紧急

**现状问题**：
- Worker 端 `/api/activate`、`/api/verify` 返回占位 JSON
- 前端已有完整 UI，但调用必然失败
- 无试用期
- 无购买入口

**产品方案**：

```
【授权流程优化】

启动 App
  ↓
检查本地 license_state
  ├─ 无 → 显示「免费试用 7 天」卡片 + 「购买卡密」按钮
  ├─ trial → 显示剩余天数 + 续费提醒
  ├─ active → 正常使用，展示到期时间
  ├─ renewal_due（<7 天到期）→ 顶部横幅 + 续费按钮
  ├─ expired → 弹窗阻断 + 续费入口
  └─ revoked/device_mismatch → 弹窗说明原因 + 客服入口
```

**需要新增**：
1. 试用期机制（后端生成试用卡密 / 前端本地标记）
2. 续费入口（跳转购买页 URL）
3. 卡密购买帮助文档链接
4. 多设备迁移功能（旧设备解绑 → 新设备激活）

## 六、架构层面的产品问题

### 6.1 数据一致性问题

| 问题 | 产品影响 |
|---|---|
| 两份订单缓存（`order_cache.db` + `order_cache.sqlite3`）用途不明 | 数据可能不一致，用户看到的数字存疑 |
| 本地缓存与远端无强同步机制 | 用户修改后未刷新可能看到旧数据 |
| Cookie 失效后本地缓存仍显示 | 给用户"假象"，实际已脱机 |

**建议**：
- 统一一份本地 SQLite
- 引入"数据新鲜度"概念（5 分钟/1 小时/1 天），过期则自动刷新
- Cookie 失效时标记所有本地数据为"离线"

### 6.2 成本与性能

| 问题 | 产品影响 |
|---|---|
| 订单同步全量拉取 | 订单多时首次同步慢（用户等待焦虑） |
| 前端本地检索（无索引） | 订单 > 10000 条时检索卡顿 |
| 无请求去重 | 快速点击多次同步会发起多次请求 |

**建议**：
- 增量同步（只拉新订单）
- 本地 SQLite 建索引（`CREATE INDEX ON orders(buyer_name, receiver_name)`）
- 前端请求节流（300ms debounce）

### 6.3 安全与合规

| 问题 | 产品影响 |
|---|---|
| `cookie.txt` 明文存储在根目录 | 泄露风险高，被上传到 GitHub 的风险 |
| 无卖家数据加密 | 订单/买家信息明文存于本地 SQLite |
| 无用户操作审计 | 多人共用 App 时无法追溯 |

**建议**：
- Cookie 使用 OS Keychain/Credential Manager 存储
- 本地数据库启用 SQLCipher
- 增加操作审计日志（写谁、何时、做了什么）

## 九、关键 PRD 片段示例

### 9.1 用户故事：批量发货失败可导出

**As a** 店铺运营，  
**I want to** 在批量发货失败后看到具体失败的订单和原因，并能导出 Excel，  
**So that** 我可以针对性地处理失败订单，不用对着 100 条订单挨个排查。

**验收标准**：
- ✅ 批量发货完成后，失败数 > 0 时显示"查看失败详情"按钮
- ✅ 展开后显示列表：订单号、快递单号、失败原因、发生时间
- ✅ 失败原因为结构化错误码（如：`ORDER_NOT_FOUND`、`TRACKING_DUPLICATE`）+ 中文说明
- ✅ 支持"导出失败列表（.xlsx）"
- ✅ 支持"仅重试失败订单"

### 9.2 用户故事：Cookie 过期预警

**As a** 店铺运营，  
**I want to** 在 Cookie 快失效时提前收到提醒，  
**So that** 我不会在批量操作中途突然被踢下线。

**验收标准**：
- ✅ App 启动时检测 Cookie 状态（轻量探测接口）
- ✅ 每 30 分钟后台检测一次
- ✅ 失败时顶部显示黄色横幅："Cookie 已失效，点击重新登录"
- ✅ 24 小时内即将失效时提前预警（如可检测到）
- ✅ 正在执行批量任务时不打扰，完成后再显示

### 9.3 用户故事：试用期

**As a** 潜在用户，  
**I want to** 下载后不用付费就能试用核心功能，  
**So that** 我能判断产品是否值得购买。

**验收标准**：
- ✅ 首次启动自动激活 7 天试用（无需输入卡密）
- ✅ 试用期间可使用所有核心功能（订单/评价/发货）
- ✅ 试用剩余天数在顶部可见
- ✅ 剩余 3 天时弹窗提醒购买
- ✅ 试用期结束后仅可查看已缓存数据，不可执行新操作
- ✅ 购买入口清晰（跳转官网 / 显示二维码 / 客服）

## 十三、总结与 Top 3 紧急事项

### 一句话总结

> TLS-shipinhao 是一款**技术架构先进但产品打磨不足**的工具型产品。主流程跑通，但**授权服务未完整、体验细节缺失、增长机制空白**，需要从"能用"升级到"好用"。

### 🔥 Top 3 必须立刻解决

1. **补完 Cloudflare Worker 授权 API**（阻塞所有付费用户，现在卡密激活本质是"假激活"）
2. **批量发货失败明细**（核心业务场景，失败率高时用户满意度崩盘）
3. **新手引导 + 试用机制**（首次流失是当前最大增长瓶颈）

### 建议行动

1. 组建小型 PM + 前端 + Rust + 后端专项组
2. Sprint 1 以**用户可以完整付费使用**为终点
3. Sprint 2 以**NPS 从 -20 提升到 +20** 为指标
4. Sprint 3 以**月活增长 30%** 为指标
