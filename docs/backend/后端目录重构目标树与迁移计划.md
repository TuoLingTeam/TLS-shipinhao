# 后端目录重构目标树与迁移计划

## 1. 重构目标

本轮重构的目标不是继续增加 crate 数量，而是把 `backend/` 收敛成一套更专业、更稳定、更容易维护的后端目录结构：

- **apps/**：可部署应用
- **modules/**：业务模块
- **shared/**：共享基础能力
- **infra/**：数据库、脚本、工具链、发布物
- **tests/**：后端专项测试

约束：

- 目录语义必须清晰，避免“业务代码、构建脚本、生成物、历史兼容壳”混放。
- `backend/` 下正式源码目录层级尽量控制在 **5 层**以内。
- 生成物不进入正式目标树语义，只保留在忽略目录。
- 保持 Rust workspace、Worker 构建链、桌面端 path dependency 全部可验证。

---

## 2. 当前 backend 的核心问题

旧结构虽然已经做过一轮收敛，但仍然存在这些问题：

1. `crates/`、`worker/`、`db/`、`scripts/`、`deploy/` 同时平铺在顶层，职责边界不够清晰。
2. 共享 crate、业务 crate、工具 crate 不在同一语义层，目录风格不统一。
3. Worker 应用与业务模块拆分标准不同，导致阅读和维护成本高。
4. `backend/src/` 这种历史残留目录曾混入 JS Worker 与静态资源，语义漂移明显。
5. `build/`、`.wrangler/`、`tmp/` 等生成物/缓存容易和正式源码树混淆。

## 4. 迁移映射表

### 4.1 应用层（apps）

| 旧路径 | 新路径 | 是否可直接移动 | 是否需要拆分 |
|---|---|---:|---:|
| `backend/worker/license-worker/` | `backend/apps/license-worker/` | 是 | 否 |
| `backend/src/admin/admin.html` | `backend/apps/license-worker/assets/admin.html` | 是 | 否 |
| `backend/src/worker/index.js` | 删除 | 否 | 否 |

### 4.2 业务模块层（modules）

| 旧路径 | 新路径 | 是否可直接移动 | 是否需要拆分 |

| `backend/crates/license-service/` | `backend/modules/license-service/` | 是 | 否 |
| `backend/crates/desktop-services/` | `backend/modules/desktop-services/` | 是 | 否 |
| `backend/crates/license-service/src/lib.rs` | `backend/modules/license-service/src/lib.rs + model.rs + repository.rs + service.rs` | 否 | 是 |
| `backend/crates/desktop-services/src/lib.rs` | `backend/modules/desktop-services/src/lib.rs + shared/review/order/delivery` | 否 | 是 |

### 4.3 共享层（shared）

| 旧路径 | 新路径 | 是否可直接移动 | 是否需要拆分 |

| `backend/crates/core/security-core/` | `backend/shared/security-core/` | 是 | 否 |

### 4.4 基础设施层（infra）

| 旧路径 | 新路径 | 是否可直接移动 | 是否需要拆分 |
|---|---|---:|---:|
| `backend/crates/tooling/build-tools/` | `backend/infra/tooling/build-tools/` | 是 | 否 |

### 4.5 删除 / 退役项

| 旧路径 | 处理方式 |
|---|---|
| `backend/crates/desktop-app/` | 已删除，由 `apps/desktop` 替代 |
| `backend/src/worker/index.js` | 已删除，Rust Worker 成为唯一正式实现 |
| `backend/apps/license-worker/build/` | 作为生成物保留并忽略 |
| `backend/.wrangler/` | 作为 Wrangler 缓存保留并忽略 |
| `backend/.cache/` | 作为工具缓存保留并忽略 |

## 5. 执行策略

### Phase A：先收拢目录语义

1. 迁移 `shared` / `modules` / `infra/tooling` 下稳定 crate。
2. 迁移 `worker/license-worker` 到 `apps/license-worker`。
3. 迁移 `db` / `scripts` / `release` 到 `infra/`。
4. 删除 `desktop-app`、legacy JS Worker、旧静态资源入口。

### Phase B：再修正路径与依赖

1. 更新根 `Cargo.toml` workspace members。
2. 更新 `apps/desktop`、`apps/license-worker`、`xtask` 等 path dependency。
3. 更新 `wrangler.toml` 与 Worker build script。
4. 更新专项测试与关键文档路径引用。

### Phase C：最后保证闭环

1. Rust workspace 元数据可解析。
2. `desktop`、`license-worker`、`license-service`、`desktop-services`、`xtask` 编译/测试通过。
3. Worker 构建脚本可在本地与 Cloudflare 环境执行。
4. 旧路径只允许存在于“迁移历史说明”文档中，不再出现在当前实现说明里。

## 6. 关键路径同步规则

### 6.1 Cargo workspace

当前 workspace members 应统一以新目录结构为准：

- `backend/shared/api-contracts`
- `backend/shared/domain-core`
- `backend/shared/security-core`
- `backend/modules/license-service`
- `backend/modules/desktop-services`
- `backend/apps/license-worker`
- `backend/infra/tooling/build-tools`
- `backend/infra/tooling/xtask`
- `apps/desktop`

### 6.2 Worker 构建链

当前 Worker 构建链应统一以新路径为准：

- 生产入口：`backend/wrangler.toml`
- 最终入口：`./apps/license-worker/build/worker/shim.mjs`
- 构建命令：`./infra/scripts/build_license_worker.sh --release`
- Worker 源码：`backend/apps/license-worker`
- 管理页静态资源：`backend/apps/license-worker/assets/admin.html`

### 6.3 生成物与缓存

以下目录不属于正式结构，只作为缓存/生成物忽略：

- `backend/apps/license-worker/build/`
- `backend/.wrangler/`
- `backend/.cache/`
