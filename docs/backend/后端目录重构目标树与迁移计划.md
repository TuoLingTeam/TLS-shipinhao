# 后端目录重构目标树与迁移计划

## 1. 目标与约束

- 目标：收敛 `backend/` 目录职责，减少过度拆分、历史壳、生成物混入、超大文件堆积。
- 约束：目录层级以 `backend/` 为根，最大不超过 **5 层**。
- 执行原则：**先删 legacy，再搬稳定 crate，再拆大文件**；每个阶段都保持可验证、可回滚。

---

## 2. 当前目录存在的核心问题

1. `backend/crates/desktop-app` 与 `apps/desktop` 职责重叠，现已确认移除前者，仅保留 Tauri 壳。
2. `backend/src/worker/index.js` 是历史 JS 兼容壳，不应继续占据正式源码层。
3. `backend/src/admin/admin.html` 是静态资源，却挂在 `src/` 下，语义不清。
4. `backend/worker/license-worker/src/lib.rs` 过大，混合了入口、路由、签名、DTO、Worker glue。
5. `backend/crates/license-service/src/lib.rs` 过大，模型、仓储、服务边界未分离。
6. `backend/crates/desktop-services/src` 过于扁平，`review/order/delivery/shared` 文件混杂。
7. `backend/.wrangler/`、`backend/tmp/`、`backend/worker/license-worker/build/` 属于生成物，不应进入目标树语义。

## 5. 可直接执行的重构 Patch 计划

### Phase 0：冻结边界

- 只把 `backend/` 视为源码、配置、测试、迁移、脚本集合。
- `backend/worker/license-worker/build/`、`backend/tmp/`、`backend/.wrangler/` 一律视为生成物。
- 先不重写业务逻辑，优先整理目录语义与路径引用。

### Phase 1：先处理最明确的 legacy 与资源路径

1. 删除 `backend/crates/desktop-app/`。
2. 删除 `backend/src/worker/index.js`。
3. 把 `backend/src/admin/admin.html` 迁到 `backend/worker/license-worker/assets/admin.html`。
4. 更新关键引用：
   - `backend/worker/license-worker/src/admin/d1.rs`
   - `backend/scripts/build_license_worker.sh`
   - `backend/README.md`
   - `backend/worker/license-worker/README.md`
   - `backend/wrangler.toml`

### Phase 2：迁移稳定且无需拆分的 crate

按顺序 `git mv`：

1. `backend/crates/api-contracts` → `backend/crates/core/api-contracts`
2. `backend/crates/domain-core` → `backend/crates/core/domain-core`
3. `backend/crates/security-core` → `backend/crates/core/security-core`
4. `backend/crates/build-tools` → `backend/crates/tooling/build-tools`
5. `backend/xtask` → `backend/crates/tooling/xtask`

同时更新：
- 根 `Cargo.toml` workspace members
- 所有 path dependencies
- `backend/tests/test_rust_workspace.py`
- 相关文档引用

### Phase 3：迁移 Worker crate

1. `backend/worker/license-worker` → `backend/worker/license-worker`
2. 把 `src/admin_d1.rs` / `src/runtime_repo_d1.rs` 改成子目录模块
3. 同步修正 `include_str!`、构建脚本、wrangler 配置路径
4. 更新 `backend/wrangler.toml` 的 build / main 路径

### Phase 4：拆分 `license-service`

1. 保留 `lease.rs / local_verify.rs / task_grant.rs`
2. 把 `lib.rs` 拆为：
   - `model.rs`
   - `repository.rs`
   - `service.rs`
   - `lib.rs` 仅做 re-export
3. 调整 `apps/desktop`、`backend/worker/license-worker`、测试中的引用路径

### Phase 5：重组 `desktop-services`

1. 保留 crate，不新增更多 crate
2. regroup 到：
   - `src/shared/`
   - `src/review/`
   - `src/order/`
   - `src/delivery/`
3. `src/lib.rs` 保持薄 façade，只暴露 re-export
4. `tests/anti_risk_pipeline.rs` 继续就近保留

### Phase 6：清理生成物与路径漂移

1. 更新 `.gitignore`：
   - `backend/worker/license-worker/build/`
   - `backend/tmp/`
   - `backend/.wrangler/`
2. 清理文档、PRD、测试中残留旧路径
3. 统一执行回归验证：
   - `cargo metadata`
   - `cargo test -p license-service`
   - `cargo test -p desktop-services`
   - `cargo test -p license-worker`
   - `cargo test -p xtask`
   - `npx wrangler deploy` 或至少构建验证

---

## 6. 执行优先级建议

- **第一优先级**：先删 legacy、先移静态资源、先收紧路径引用。
- **第二优先级**：再搬稳定 crate，避免在大文件拆分前继续增加路径漂移。
- **第三优先级**：最后拆大文件（`license-worker` / `license-service` / `desktop-services`）。

---

## 7. 验证策略

每完成一个阶段，至少执行对应验证：

- Phase 1：`cargo check -p license-worker`、`sh backend/scripts/build_license_worker.sh --release`
- Phase 2~3：`cargo metadata`、`cargo check -p license-worker`
- Phase 4~5：目标 crate 的 `cargo test`
- Phase 6：完整后端回归 + Worker 构建/部署验证
